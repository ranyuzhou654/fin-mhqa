# benchmark_v1 质量检查（S4）

2026-09-23。对 S3 生成的题目做三项检查：改写题面、歧义检查、检索可达性诊断。最终得到 Dev 50 道、Test 100 道，**待用户抽查 20 道 Test 题后，在 S5 冻结**。所有模型调用都只看到题面，从不接触答案。

## 结果

| | Dev | Test |
| --- | ---: | ---: |
| 最终题数 | 50 | 100 |
| 采用改写后题面 | 49 | 99 |
| 因歧义删除（正式题 / 后备题） | 0 | 5 / 4，全部是 T6 |
| 由后备题补入 | 0 | 5 |

题型数量与设计一致：Test 为 T1 16、T2 14、T3 14、T4 18、T5 26、T6 12。Test 的 T6 中，第三季度 5 道、2023 年上半年 3 道、语料外公司 3 道、2025 全年 1 道。

## 1. 改写题面（DeepSeek）

每道题调用一次 DeepSeek，把模板化的题面改写得更自然。改写结果用规则检查，任何一项不合格就退回模板原文：
- 公司名、指标名称、期间、口径、选择条件、运算要求、公式定义、单位和小数位数都必须逐字保留；
- 不得出现新的数字或新的公司；
- 长度不得超过原文的两倍。

235 道（含后备题）中有 229 道改写合格；不合格的主要是把「所占比例」改成了别的说法。

## 2. 歧义检查（Sol + DeepSeek）

每个 Judge 对每道题独立调用一次，只判断题面是否有歧义，不回答题目。任一 Judge 标记即进入复核。

**第一轮发现了一个模板缺陷，因此在冻结前修订了 S3。** 第一轮 DeepSeek 标出 25 道，指出合并口径的「净利润」可能被理解为归母净利润。这是真实的歧义：中文财经语境里「净利润」经常指归母净利润。两个 Judge 还都指出，语料外公司题的「差额」没有说明方向。修订内容：
- 合并口径的净利润改写为「净利润（含少数股东损益）」，相关比率的公式也一起改。母公司报表没有少数股东，保持原样。
- 语料外公司题改为「A 减去 B 同期同一指标，保留正负号」。

修订后重新改写并判定。第二轮中，**所有可回答题都没有被任何 Judge 标记**。第一轮的全部判定原样保留在证据里。

第二轮的标记全部落在 T6（无法回答）题上，按事先写定的规则处理：

- **保留（15 条，记录复核结论）**：第三季度、全年、2023 年上半年这三类题，如果标记只涉及期间或计算方式，内容其实是在复述「半年报不覆盖这个期间」，这正是题目预期的无法回答前提。年化推算也不是可接受的答案。
- **删除（9 道）**：带有其他理由的 T6 标记一律删除，即使细看也是在复述同一前提，也不事后放宽规则。例如 DeepSeek 指出蒙牛乳业是港股公司，或称全年题「口径」不清。

T6 的后备题原先只有 6 道，替补不够，于是只把 T6 的后备比例提高到 100% 并重新划分。Test 的正式题完全不变；Dev 的 T6 有 2 道因此被替换，这只影响 Dev。

DeepSeek 在第二轮有 7 次调用遇到服务端 503，重试后仍失败，没有给出判定。这 7 题重新调用一次后得到判定；失败记录保存在本地 `data/bench/s4_v1r1/failed_attempts/`。

## 3. 检索可达性诊断

对每条事实，用标准查询（公司、口径、报表名、指标名、期间）以 hybrid 模式检索前 5 名。命中条件：返回同一个块，或同一份报告中含有该原文数值和指标名的块。

163 条事实中有 148 条命中。题目至少有一跳没命中的，打上 `retrieval_miss` 标签：Test 21 道，Dev 7 道。**按设计不删题**：检索不到说明对 Agent 更难，而不是题目有问题。

## 用量

- DeepSeek：改写输入 12.1 万、输出 68.6 万 token；判定输入 17.8 万、输出 23.8 万 token（两轮合计）。
- Sol：判定输入 664 万、输出 4.8 万 token（两轮合计）。输入量大，主要来自 Codex CLI 的固定上下文开销。
