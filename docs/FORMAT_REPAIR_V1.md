# 技术评估：带校验反馈的格式修复

2026-09-25。在 benchmark_v1 的 Dev 集上评估。「+修复」配置与 S6 的对应配置只差一个开关 `format_repair`；每个配置跑 3 次，模型与接口相同。评分和配对 bootstrap 的方法同 [S6](BENCHMARK_V1_S6_BASELINES.md)。

## 动机

S6 中，B2 共 9 道题报错，B3 共 8 道，其中 16 道是模型输出的 JSON 不符合 schema：缺少 `reason`、`context`，或多出 `answer_unit_note` 这类字段。DeepSeek 的 JSON 模式不强制校验 schema，这类错误大约占了 Agent 失分的一半。

## 做法

模型每次输出后，按该步骤的 JSON Schema 校验。如果不合格，把原来的输出和具体的校验错误作为对话发回，要求「保持原来的决定和内容不变，只修正格式」，最多修复 1 次。修复调用不计入 Agent 的决策预算，但它消耗的 token 计入成本，修复次数也单独统计。所有未被采纳的输出都原样保留。代码见 [openai_compat.py](../src/finmhqa/agent/openai_compat.py)，默认关闭。

## 结果

| 配置 | 3 次准确率 | 均值 | 报错 | 实际修复次数 | 每次输入 token | 平均模型调用 |
| --- | --- | ---: | --- | --- | --- | ---: |
| B2 单模型 | 90 / 92 / 96% | 92.7% | 4 / 4 / 1 | — | 236–273 万 | 4.23 |
| **B2 + 修复** | **100 / 100 / 96%** | **98.7%** | **0 / 0 / 0** | 1 / 3 / 7 | 255–288 万 | 4.35 |
| B3 四角色 | 96 / 96 / 88% | 93.3% | 1 / 2 / 5 | — | 347–368 万 | 5.21 |
| **B3 + 修复** | **94 / 96 / 100%** | **96.7%** | **0 / 0 / 0** | 2 / 4 / 5 | 364–426 万 | 5.32 |

| 配对比较 | 准确率差 | 95% 置信区间 | 变好 / 变差题数 |
| --- | ---: | --- | --- |
| B2 → B2 + 修复 | **+6.0 个百分点** | **[+2.7, +10.0]** | 9 / 0 |
| B3 → B3 + 修复 | +3.3 个百分点 | [−1.3, +8.0] | 7 / 3 |
| B2 + 修复 → B3 + 修复（加修复后的多角色效果） | −2.0 个百分点 | [−4.7, 0.0] | 0 / 3 |

结论：
1. **格式修复消除了全部报错**，两个配置、6 次运行共 0 道报错。修复实际被触发 22 次，最常见的原因是缺少 `reason`（7 次）和多出 `*_note` 字段（6 次）。
2. **对单模型 Agent 的提升是显著的**：+6.0 个百分点，置信区间不包含 0，9 道题变好、0 道变差。代价是输入 token 大约多 5%，平均模型调用多 0.1 次。
3. **对四角色 Agent 的提升方向一致，但不显著**（区间包含 0）。原因是 B3 去掉格式错误后，剩下的失分另有来源（见下）。
4. **加上修复后，单模型反而略优于四角色**：差 2.0 个百分点，区间上界正好为 0；3 道题单模型对、四角色错，没有反例。B3 剩余的 5 次失分全部是「拒答」：Verifier 否决后再次提交仍未通过，或重规划次数耗尽。这些题 B2 都能答对。也就是说，**核验角色让系统更保守，在这套题上多拒答了一些本来能答对的题**。这只是 50 题、3 次运行的开发集观察，区间边界贴着 0，需要在更难的题上验证。

## 限制

- 仅 Dev 50 题，每个配置 3 次运行。
- 修复依赖模型能按反馈改正；如果修复后仍不合格，按报错处理，本轮没有发生。
- 修复只改格式，不应改变决定。这是通过提示约束的，没有程序化比对修复前后的内容；原始输出都保留，可以复核。

证据：[B2 对比](evidence/format_repair_v1/b2_flat.json)、[B3 对比](evidence/format_repair_v1/b3_graph.json)、[加修复后的 B3 与 B2](evidence/format_repair_v1/b3_vs_b2_with_repair.json)、[审计](evidence/format_repair_v1/)（300/300 通过）、[运行日志](evidence/format_repair_v1/format_repair_driver.log)。本轮检索错误为 0。B3+修复第 3 次运行曾在 22/50 时应用户要求暂停，部分结果移到本地 `aborted_*` 目录，之后从头完整重跑。
