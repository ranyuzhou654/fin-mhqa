## 数字与结论的使用边界

以下全部尚无本项目运行证据：5,000 种子、2,350 候选、1,311 成品、Train 1,049 / Test 262；Replan 0.376→0.392；SFT Correctness 0→0.339、Faithfulness 0.239→0.263；GRPO Correctness 0.401、Faithfulness 0.317；32B 基线 0.392/0.301。

数量可作为预算估算的参考规模，最终按真实质量通过量记录；性能值仅是待验证的参考叙述，不能用作预填结果或必须追平的目标。不能通过删题、调整标签、放宽阈值或挑选运行轮次使数字接近参考值。

“Replan 反馈不足是主要瓶颈”“两阶段训练缓解目标冲突”“小模型超过大模型”都必须由失败归因、对照和消融支撑。超越基线是研究假设；未超越时同样交付真实结果和失败分析。原文中 SFT 只学格式、GRPO 才学策略的因果归因也需实验，不能先行断定。

## 采纳后的实施顺序

### 1. 在 M3 小样前明确评测契约

- 保留 M3 的 20 道手写多跳开发题（桥接 8、比较 8、聚合 4），答案与每跳证据先核验；沿用至少答对 8 题、平均工具调用不超过 6 次等运行门槛。该门槛只证明小样流程可用，不证明适合直接批量生产。
- 在 M4 批量化和 SFT 前，明确 Train/Dev/Test 三套数据。原 1,049/262 两分法缺独立 Dev，实际数量待质量统计后确定；手写开发题及其改写不进入最终 Test。
- 以问题近重复、来源证据链、公司集合与指标等分组隔离，记录分组策略和泄漏检查。跨公司比较题涉及多个公司，不以普通随机分层替代证据链隔离。
- 固定语料、标签版本、工具 schema、模型配置、提示词、预算、评分器及测试集哈希；测试答案和 Judge 输出不进入被测 Agent 上下文。
- 新公司或新期间泛化需要额外对应留出集；同一组财报上的测试只支持该语料范围内的结论。

### 2. 建立最小 Agent 与可诊断运行记录

保留 Planner–Executor–Verifier–Synthesizer 和有上限的 Replan 方案。共享状态明确存储问题与子任务、证据来源、公司/期间/单位、已尝试查询、未解决项、工具预算及终止原因。证据不足、证据冲突、工具错误分别记录，不能全部包装为“没有找到”。数值运算交给可复核计算工具。

保存实际消息、工具参数和完整工具响应、最终答案与引用、简短决策依据、时间与 token 用量。不要把事后生成的解释当作模型真实轨迹，也不依赖供应商不可访问的内部思维链。先用开发题确定哪些问题可由提示词或工具约束解决，再考虑训练。

### 3. 小批合成通过后再扩大

采纳种子 QA → 多跳拓展 → 规则过滤 → 四项语义检验 → 可达性验证 → 独立 Judge 的质量思路。四项检验至少明确为：源证据确实支持答案、确实需要多个信息步骤、推导/计算成立、题意与口径无歧义；各自输出结构化结论和原因。多次 LLM 判断不能替代原 PDF 和规则核算。

每道候选保留原文锚点、source/chunk 哈希、每跳证据、答案类型、单位/期间、计算表达式和拒绝记录。先完成一个小批次，检查通过率、人工抽检差错、每条有效样本费用、检索吞吐和超时，再决定批量规模及预算。

可达性是诊断信息。训练示范可筛选正确且证据充分的轨迹；测试题只要依据充分且题目有效，不能因当前教师答错或检索失败而删除。数据划分先于面向训练的成功轨迹筛选，防止最终测试仅剩教师已会的题。教师见过或参与生成的合成测试，应明确披露，并补充独立人工编写、源页核验的留出题。

### 4. 通过对照优化架构

先固定教师、语料和预算，在 Dev 上比较：固定检索回答 → 分跳规划 → 结构化失败反馈与 Replan → 受控脚注/原页读取 → 上下文组织。每次只改变待验证因素，记录题目级变化，再做去组件消融；不要提前认定 Replan 是主要瓶颈。

另比较关闭 reranker、固定 hybrid 与动态工具选择、禁用 Replan；它们是实验配置，不能静默改动既有验收配置。汇报多次运行的均值与波动、配对题目差异、成本和延迟，不挑最好一次。

比较学生与教师时，同时保留相同运行方式及工具/上下文预算下的对照。图模式教师对扁平模式学生只能说明系统配置差异，不能单独归因于模型大小或训练效果。

### 5. 最后进入 SFT 与 GRPO

教师/学生可不同厂商；先统一工具协议与轨迹表示，再转换学生模板。SFT 仅用 Train 轨迹，Dev 选配置/checkpoint，Test 不用于早停或调参。以 Base→SFT 对照验证工具格式、答案及引用的变化，不预设 Base 为零分。

GRPO 先验证多轮真实工具 rollout 的奖励和训练样本一致性，再训练。实际采样的 token、mask 和策略概率应与训练前缀一致；不可通过改写前缀或重编码文本伪装同一条采样轨迹。保留奖励各分项与失败例，检查堆砌引用、单位投机、无效重复检索等行为。

Correctness、证据支持、引用精确率、分跳覆盖可组合，但证据 ID 命中不能替代语义支持。两阶段权重作为候选实验，与单阶段及去掉关键奖励项对照；先确认是否存在目标冲突，再解释缓解效果。模型、算力与训练预算分别审批。

## 统一评测口径

| 层级 | 指标 | 必须控制的误判 |
| --- | --- | --- |
| 检索 | Hit@K、每跳及全跳证据覆盖；有充分相关度标注后再用排序指标 | 至少命中一个 chunk 不等于完整回答；接受经过源页审核的等价证据 |
| 答案 | Correctness | 同时检查公司、期间、口径、单位；数值容差按题型精度明确，不能统一 ±1% 掩盖错误 |
| 依据 | Faithfulness、引用精确率/覆盖 | ID 相交仅是代理指标，需核验答案陈述是否被引用支持 |
| 行为 | 工具合法率、恢复成功率、无效重试、合理拒答 | 服务错误与证据不足分开；评测错误计失败，不能从分母剔除 |
| 资源 | 平均/P95 延迟、工具调用、token、单题费用 | 相同预算下比较质量，同时报告为增益付出的成本 |

规则可判定的数值/实体先用确定性程序，语义支持使用固定 Judge 并以人工样本校准。Judge 与教师分开有助于降低自评偏差，但仍可能共享错误，不能称为绝对真值。项目设计中“全部 LLM Judge”与实现示例中的混合评分不一致，后续采用上述明确分工并版本化。
