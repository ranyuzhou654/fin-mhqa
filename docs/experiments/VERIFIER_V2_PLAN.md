# 核验角色 v2：设计与事先登记

结果见 [VERIFIER_V2_RESULTS.md](VERIFIER_V2_RESULTS.md)。

2026-09-25，在任何 v2 运行之前写定。

## 起因

[故障注入第 1 轮](FAULT_INJECTION_V1_RESULTS.md)显示，核验角色 v1 有两个具体缺陷：

- **冲突时无限拒绝（F3）**：35 次误拦的理由都是 CONFLICT。候选已经采用正式报表的数值，而且与附注一致，v1 仍要求「解释摘要表为什么不同」，逐轮拒绝，直到预算耗尽。结果 6 个正确候选变成了拒答。根源是 v1 提示词只写了「明显冲突不能随意挑一个值」，没有给出来源优先级。
- **不核对期间列（F2）**：17 个被误导的候选中，12 个被 v1 接受。它只确认「数字在原文里存在」，不核对这个数字所在列的期间表头，也不与其他来源对照。

## 改动（`verifier: "v2"`，v1 保持冻结）

- **提示词**：`VERIFIER_V2 = VERIFIER +` 4 条补充规则：
  1. **来源优先级**：正式报表及附注 > 主要会计数据等摘要表 > 叙述。候选采用正式报表且有第二来源一致、并在说明中指出冲突时，视为冲突已解决。
  2. **期间列核对**：核对关键数值所在列的期间表头；如果其他已观测来源显示该值属于另一期间，报 PERIOD_MISMATCH。
  3. **单一来源交叉核对**：关键数值只有一个来源、剩余工具调用不少于 2 次，并且此前没有为这个数值要求过核对时，报新增的 NEEDS_CROSS_CHECK 代码，要求查主要会计数据或附注的同期数值。每个数值最多要求一次，预算不足时不得据此拒绝。
  4. **不重复拒绝**：同一问题已经提出过、而新证据不能进一步消除时，按第 1 条直接裁决。
- **输入**：核验角色 v2 额外收到 `previous_rejections`（此前的拒绝记录）和 `budget`（剩余工具、检索、模型调用和重规划次数）。
- **其余不变**：规划、执行、预算、格式修复都与 B3 + 修复相同。配置文件为 [bench_b3_graph_repair_verifier_v2.json](../../configs/bench_b3_graph_repair_verifier_v2.json)。

## 评估（事先登记）

- **运行**：
  - 故障条件：F1/F2/F3 各 1 轮，每轮 44 题，使用同一份注入计划（sha256 `ea43b082…`）。
  - 干净 Dev：跑 3 次，检查有没有退步。
  - 严格串行，脚本为 `scripts/run_verifier_v2.sh`。
- **主要比较：B3v2 相对 B3（v1）**，按故障类型分别计算有效计划上的准确率、被误导率和拒答率，做配对 bootstrap。
- **核验角色机制指标**：纠正、损害、漏过的题数（`fault_verifier_effect.py`），以及误拦次数和拦截次数。
- **成功判定**：以下三条同时满足才算成功。
  1. F3 的拒答率下降，并且 F3 准确率不降低。
  2. F2 的被误导率不升高，且纠正题数不少于 v1 的 5 题。
  3. 干净 Dev 准确率相对 B3 + 修复（96.7%）不显著下降：配对差的 95% 区间下界不低于 −5 个百分点。
- **次要比较**：B3v2 相对 B2 + 修复，看改进后的多角色是否超过单模型。
- **成本**：模型调用次数、token、耗时。

## 已知偏差（如实报告）

- **v2 是看过这批 Dev 故障结果之后设计的**：在同一批题和同一份注入计划上评估，结果会偏乐观。规则写成通用的来源优先级和核对规则，没有写入任何具体题目或数值，但偏差仍然存在。
- **Test 集仍然不用于这项实验**：如果以后要做不偏的验证，需要在 Test 上登记配置后，一次性运行。
- **只有 1 轮**：故障条件只跑 1 轮，区间会比较宽。
