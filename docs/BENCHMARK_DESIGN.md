# 评测集 benchmark_v1 设计

2026-09-23。项目转为 Agent 项目后，评测集用来比较不同 Agent 架构的优劣，不用来训练。现有 dev20 已饱和：flat 基线与 DeepSeek 均为 20/20，无法区分架构。设计已于 2026-09-23 经用户确认。

## 目标

1. **难度足以区分架构**：包含三跳以上的推理、比率与增长率计算、续表与单位陷阱、以及无法回答的题。
2. **答案由程序计算**：每个答案都由经源页核验的事实经确定性计算得出，不依赖 LLM 出答案。
3. **Test 冻结且隔离**：Test 部分冻结后不再修改；Agent 运行时看不到任何 gold；Test 只用于最终报告，不用于调参。

## 1. 事实台账（fact ledger）

现有已核验事实只有 22 条（3 个指标），不够用。另外语料中 2,780 个结构化表格块里有 1,367 个的单位是「未标注」，不能直接自动抽取。因此先建立一个核验过的事实台账，所有题目只从台账中取数。

**范围**：10 家公司 × 13 个金额指标 × 2 个期间，全部为合并口径，共 260 条。另外加上 4 个指标（营业收入、净利润、经营活动现金流量净额、资产总计）的母公司口径，共 80 条，专门用来出口径陷阱题。合计约 340 条。

| 类别 | 指标 | 期间 |
| --- | --- | --- |
| 利润表 | 营业收入、营业成本、销售费用、管理费用、研发费用、净利润、归属于母公司股东的净利润 | 2025H1，2024H1（上年同期列） |
| 现金流量表 | 经营活动产生的现金流量净额、投资活动产生的现金流量净额 | 2025H1，2024H1 |
| 资产负债表 | 资产总计、负债合计、归属于母公司所有者权益合计、货币资金 | 2025-06-30，2024-12-31 |

**每条事实记录**：公司、指标、口径、期间、原文数值字符串、单位、单位来源（表头或报告级声明所在的 chunk_id）、数值所在的 chunk_id、页码、源 PDF 的 SHA256。

**抽取与核验**：从三大报表的 table_md/table_kv 中半自动抽取候选值。只有全部通过下列检查的事实才能进入台账：

- **原文检查**：数值字符串逐字出现在所引 chunk 的文本里；表名包含报表名称和口径。
- **单位检查**：单位必须有明确来源。表头标注「未标注」时，必须找到同一张表的原表头或报告级单位声明，并记录其 chunk_id。
- **会计恒等式**：资产总计 = 负债合计 + 所有者权益合计（归母权益 + 少数股东权益），允许的误差不超过原表的末位精度。
- **跨表一致**：合并报表中的营业收入、归母净利润、经营现金流，应与第二节「主要会计数据」表的数值一致。

没有通过的事实列入复核清单，不进入台账，也不做猜测修补。

## 2. 题型与数量

合计 150 题：Dev 50 题，Test 100 题。

| 题型 | 说明 | Dev | Test |
| --- | --- | ---: | ---: |
| T1 单跳陷阱 | 单个事实，但设置口径、期间或单位陷阱（例如母公司与合并口径同时出现） | 8 | 16 |
| T2 两公司运算 | 两家公司的同一指标求差、求和或比较 | 8 | 14 |
| T3 条件桥接 | 先按指标 A 选出公司，再查询该公司的指标 B（dev20 的题型） | 8 | 14 |
| T4 比率与增长 | 毛利率、净利率、同比增长率、跨报表比率（如经营现金流 / 净利润） | 8 | 18 |
| T5 三跳及以上 | 例如：在 3 家公司中按营收排序，再计算选中公司的比率 | 12 | 26 |
| T6 无法回答 | 报告未覆盖的期间（如 2025 年第三季度）、语料外的公司、报告中没有披露的指标 | 6 | 12 |

另设一个**证据位置标签**：Test 中至少 20% 的题，至少有一跳的证据位于续表、单位未标注的表格，或只能从报告级声明中确定单位。这个标签只用于分层统计，不单独作为题型。

**需要扩展的工具**：T4、T5 需要计算比率和增长率。计算器增加 `ratio`（a/b）和 `growth`（(a−b)/b）两种运算，输出单位为 `%`。这是 Agent 能力的变化，需要配套测试。

## 3. 生成流程

1. **从台账组合题目**：按题型模板选择事实组合，用 Decimal 计算答案，并记录推导表达式和每一跳对应的事实 ID。
2. **生成题面**：先用确定性的中文模板，题面必须包含公司、指标、口径、期间、单位和舍入要求。可以选择用 DeepSeek 做改写，使措辞多样；改写只看得到题面，看不到答案。改写后用规则检查以上要素是否完整保留，不合格就退回模板原文。
3. **答案复算**：用计算工具和一个独立实现的函数各算一次，两者结果必须一致。
4. **歧义检查**：由两个 Judge 分别判断题面是否存在歧义，其中至少一个不是 Agent 所用的模型。任一 Judge 判为有歧义的题，要么进入复核，要么删除，并记录原因。
5. **可达性诊断**：检查每一跳的证据是否能被检索服务召回。结果只作为难度标签，**不能因为检索不到就删除 Test 中的题**。

## 4. 划分与防泄漏

- 按事实组合对题目分组，同一组的题只能全部进入 Dev 或全部进入 Test。用固定随机种子分配。
- **Test 中的每道题至少包含一条从未在以往开发题中出现过的事实。** 以往开发题指 dev20、12 题桥接小样和 30 题合成小样；这些题及其改写只能放进 Dev。
- 近似重复检查：任何 Test 题与 Dev 题的字符 n-gram Jaccard 相似度不超过 0.8。
- 冻结文件：
  - `benchmark_v1/{dev,test}/questions.jsonl`：只含 id 和题面。
  - gold 单独存放。
  - manifest 记录台账、生成代码、题目和 gold 的哈希。
- 运行器在跑 Test 时必须显式加 `--final` 参数，并且只接受事先登记的配置；每次 Test 运行都要记录。

## 5. 评分

| 层级 | 指标 |
| --- | --- |
| 答案 | 正确率：舍入后数值完全相等、单位一致、桥接题选对公司。按题型分别报告 |
| 拒答 | T6 的拒答召回率；可回答题上的误拒率 |
| 依据 | 引用有效性（规则判定）；各跳关键证据被最终引用覆盖的比例（程序判定）；Judge 给出的依据评分，并注明未经人工校准 |
| 成本 | 模型调用次数、工具调用次数、token 数、平均与 P95 延迟 |

每个配置在 Dev 上跑 3 次；最终候选配置在 Test 上跑 3 次。报告：
- 所有运行的均值和波动。
- 逐题配对的差异，以及准确率差异的 bootstrap 置信区间。
- 不挑选最好的一次运行，失败和报错都计入分母。

## 6. 对照基线

| 编号 | 配置 |
| --- | --- |
| B0 | 闭卷：不检索，直接回答。用于衡量模型凭记忆能答对多少 |
| B1 | 固定流程：检索一次，然后回答（原设计 §5.13 的固定 Pipeline） |
| B2 | flat 动作策略：单模型循环调用工具 |
| B3 | 四角色结构化图，即 teacher_v2 配置 |

之后的架构消融都以 B2、B3 为基准，每次只改变一个因素。

## 7. 实施步骤与成本估计

| 步骤 | 内容 |
| --- | --- |
| S1 | 计算器增加 ratio 和 growth 运算，并补测试（已完成：版本化为 calculator v2，配置中声明 `"calculator": "v2"` 才启用；v1 的提示词与 schema 保持不变） |
| S2 | 抽取事实台账，运行四类核验；生成未通过事实的复核页（已完成：340 条候选准入 298 条，见 [FACT_LEDGER_V1](FACT_LEDGER_V1.md)） |
| S3 | 题型模板、题目生成器、划分与防泄漏检查（已完成：Dev 50 / Test 100 及后备题，见 [BENCHMARK_V1_GENERATION](BENCHMARK_V1_GENERATION.md)） |
| S4 | 质量关：规则检查、歧义 Judge、可达性诊断（已完成，待用户抽查：见 [BENCHMARK_V1_QUALITY](BENCHMARK_V1_QUALITY.md)） |
| S5 | 冻结评测集；运行器增加评测集模式和 Test 保护；评分脚本支持拒答和比率题（已完成，见 [BENCHMARK_V1_FROZEN](BENCHMARK_V1_FROZEN.md)） |
| S6 | 在 Dev 上跑 B0–B3，每个配置 3 次 |

成本估计：DeepSeek 跑一次 dev20 约用 134 万输入 token。按此推算，Dev 50 题 × 4 个配置 × 3 次，约需 4,000 万输入 token。

## 已确认的决定（2026-09-23）

1. 规模：Dev 50 / Test 100。
2. 歧义检查的 Judge：Sol 与 DeepSeek，其中 Sol 不是 Agent 所用的模型。
3. 用户抽查 20 道 Test 题的题面和答案。
4. 保留母公司口径的陷阱题（80 条事实）。
