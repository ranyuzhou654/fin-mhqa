# M3 四角色 Agent、对照与修复结果

后续[M3.1上下文与预算实验](AGENT_M31_RESULTS.md)已完成固定20题复测（17/20）。本文保留此前原始对照及发布修复结果，不被新分数覆盖。

2026-09-14。已实现LangGraph Planner–Executor–Verifier–Synthesizer、有限重规划、真实检索/计算及事件审计。使用内置gpt-5.6-sol和原9,322条正式索引，新增20道冻结开发题（8桥接、8比较、4聚合）。题目由主代理基于此前审核事实重新编写，含重复来源事实；不是人类独立出题或盲测，不进入Test/Train。

所有组使用相同题目、语料、教师、计算器、top5/n_cand30及预算上限：6次检索、8次总工具调用、10次所有角色模型调用。每题轮换组别顺序，4个case并发，客户端串行检索。每组只运行一次，所有失败保留。

三组均满足预设运行门槛：答对≥8/20、平均工具调用≤6、无顶层error；60/60轨迹通过原始模型事件、实际工具参数及计算重放审计。预算终止按答错处理，并不因为error字段为空就算成功。完整[评分](../evidence/agent_dev20_v1/original_run/evaluation.json)、[审计](../evidence/agent_dev20_v1/original_run/audit.json)与[逐题轨迹](AGENT_DEV20_TRAJECTORIES.md)均已保存。

这里的正确只核对最终数值、单位及桥接选中公司，不等于解释中每项陈述均被充分引用支持。动作策略更快、最终数值分数更高，不能据此判定其证据质量更好。原分跳字符串锚点命中分别为44/48、46/48、45/48；等价单位/舍入表达可能漏记，保留诊断原分数。

耗时包含并发请求及串行检索等待；只有一次运行，不提供稳定性、显著性或独立泛化结论。Verifier使用同一教师，不是独立Judge。

## 观察到的失败与改进依据

第2题两个四角色组补齐证据后，在第10次模型调用通过了Verifier，但没有额外预算供Synthesizer润色，最终拒答。原结构化组唯一数值失败来自这一终止路径。独立润色还可能改写之前已核验的解释。

第6题结构化反馈指出泸州老窖收入缺少单位与期间表头；Planner改变查询补齐后成功。通用反馈组仍未补齐单位，触及模型预算。这支持继续研究具体反馈的作用，但一个配对案例不能证明它是主要瓶颈或有稳定增益。

固定抽查题按题目文件哈希选出005、002、018、008、019，检查三组实际返回文本、最终引用及重规划，共15条；[抽查记录](../evidence/agent_dev20_v1/trace_sample_review.json)。发现：部分数值正确答案引用的目标表格缺单位；原structured-018采用已舍入的120.33亿元参与加总，最终两位小数正确，但解释中的更多小数不能当作原始数据精度。所有原分数不改写。这是代理文本核查，不是新增PDF视觉审核或独立Faithfulness评分。

## 后续修复与复测

已增加synthesis=verified：Synthesizer保留为图节点，重新检查数值及引用后原样发布已核验候选，不再调用模型或改写解释。旧synthesis=model模式和完整执行代码快照保留。提示词、工具、预算和20题评分不变；完整20题已重新实跑一次：数值/实体正确19/20，平均工具调用4.70，模型调用128次，平均耗时167.69秒，顶层error为0，20/20轨迹审计通过，运行门槛PASSED。见[修复版评分](../evidence/agent_dev20_v1/verified_run/evaluation.json)、[审计](../evidence/agent_dev20_v1/verified_run/audit.json)与[真实轨迹](AGENT_VERIFIED_TRAJECTORIES.md)。

相较原structured组，模型调用143→128，减少15次（10.49%）；检索60→64、总工具90→94，数值正确率仍19/20。第2题由失败转为成功，第7题由成功转为失败；后者在6次检索后补到了比亚迪单位说明，但已没有模型预算再次核验。故本轮降低了模型调用开销、消除了核验后再改写解释的路径，没有证明整体正确率或检索效率提升。每次发布少一次模型调用是确定的机制变化；两次运行的总数差还包含随机查询路径差异，不能把全部差异归因于修复。

五个独立故障实验分别遮蔽首轮单位/期间、制造空召回、模拟超时及追加会改变公司比较结果的合成冲突值。原始HTTP返回单独保留；冲突文本明确提示冲突，仅检验受提示处理，不声称盲检。结果不计入上述20题分数。原五次实跑中，空召回、超时、部分单位遮蔽和部分期间遮蔽均得到260.14亿元；冲突被Verifier识别并阻止发布，但进一步核对未在预算内完成，最终拒答，数值恢复4/5。见[原故障记录](../evidence/agent_dev20_v1/recovery_v1/evaluation.json)。

复核发现v1遮蔽不完整：unit_source仍包含人民币千元，table_title仍包含2025年半年度。因此其中两项不能证明完全缺少单位/期间时的恢复能力。原记录与[更正说明](../evidence/agent_dev20_v1/recovery_v1/masking_erratum.json)保留，v2将text及相关单位、期间、表名、章节字段一起遮蔽，只重做这两项；修正版两项最终数值均正确（2/2）：单位遮蔽下Planner主动补查，并在Verifier要求后补齐合并口径引用；期间遮蔽未观察到专门缺失检测，后续正常查询重新获得相关信息。见[修正版记录](../evidence/agent_dev20_v1/recovery_v2/evaluation.json)与[逐项故障审核](AGENT_RECOVERY_REVIEW.md)。不能把这两项结果称为普遍缺失检测能力，也不能把冲突拒答算作成功解决冲突。

共7次故障运行的事件/参数/计算/发布一致性审计通过。初版审计器误要求超时响应包含results字段，已修复为接受结构化error，仍拒绝同时缺少results/error的响应；原审计报告evaluation.initial_audit.json保留，实际轨迹与数值评分不变。
