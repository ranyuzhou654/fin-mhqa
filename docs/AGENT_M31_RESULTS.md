## 新能力的实际证据

10题使用上下文读取，共17次：前页4、所在页4、原表5、单位候选4，零上下文工具错误。5题最终引用包含上下文返回的ID；这些ID也可能出现在search结果，因此不是5题独占收益或完整引用质量得分。

20/20轨迹通过模型事件、真实工具参数、计算重放、最终发布一致性检查，并逐条重放上下文原文：[审计报告](evidence/agent_m31_v1/dev20/audit.json)。所有执行源文件哈希与运行清单一致；语料、健康状态前后一致。原表/相邻页只返回已准入chunks，并不保证完整PDF页或自动识别跨页续表。

预留验证预算有契约测试覆盖：在剩余两次调用时只允许finish，最后一次核验通过才发布；最后核验拒绝则不发布。本轮20题没有触发 finalize_only schema 收窄事件（0次），不能把模型调用减少直接归功于这一分支。007在第9次调用核验失败，剩一次不足以重写并重验，因此按预算规则拒答。

## 失败定位

- **006：目标证据未取齐。** 泸州老窖单位/期间已通过前页补齐；随后贵州茅台现金流首段不含目标净额，同parent_table读取没有跨到另一父表ID的续页。8次工具用尽，最后只找到母公司口径值，模型拒绝替代合并值。需要检验next_page选择和为最终计算预留工具额度。
- **007：单位补齐，引用仍有缺口。** 两页单位候选使模型找到适用千元说明，归母金额计算正确；Verifier指出比较阶段收入引用来自管理层构成表，缺直接合并利润表引用。剩余一次模型调用不能完成修订加再核验，拒答。
- **011：可达证据没有被策略利用。** 单位候选只读cursor=0，后续转向搜索而非next_cursor，最终单位未确认，7次工具/7次模型后主动拒答。不能宣称单位声明不存在于语料。

单位候选当前为宽匹配，局部表格正文会排在报告总声明之前；固定[真实语料探针](evidence/agent_m31_v1/context_probes.json)证明所需声明可以经分页读取，同时暴露额外工具成本。这一实现先保留为可审计实验版本，不能仅凭功能完成就推广为性能更好的默认策略。
