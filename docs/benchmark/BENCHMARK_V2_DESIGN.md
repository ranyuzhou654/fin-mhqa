# 多轮对话评测集 benchmark_v2 与对话策略评估：设计（事先登记）

2026-10-16 写定，任何多轮对话的模型运行之前。对应路线图 P4。

## 目标

用户在真实使用中会连续追问，而且后一轮通常会省略前文已经说过的内容。例如「宁德时代同期呢？」「两家里较高的那家，它的研发费用是多少？」「不对，我要的是母公司口径」。

这一轮要回答两个问题：
1. 用哪种方式把对话上下文交给 Agent，后续轮次答得最准？
2. 跨轮次带上已经核验过的证据，能否在不降低准确率的前提下减少检索和 token？

## 一、评测集怎么生成

做法与 benchmark_v1 相同：只从 [事实台账](FACT_LEDGER_V1.md) 的 298 条已核验事实出发，每一轮的答案都由程序用 Decimal 计算，不调用任何模型。代码见 [dialogue.py](../../src/finmhqa/bench/dialogue.py) 与 [generate_dialogues.py](../../scripts/generate_dialogues.py)。

**五类对话链**：

| 类型 | 轮次 | 例子 | 考察的现象 |
| --- | --- | --- | --- |
| D1 桥接 | 3–4 | ① 五粮液上半年营收？② 亿纬锂能同期呢？③ 两家里较高的那家，2025 年 6 月 30 日负债合计是多少？④ 这个指标比上期增长了多少？ | 省略指标和期间、比较指代、代词 |
| D2 差额 | 3 | ① A 的营业成本？② B 呢？③ 前者减去后者是多少？ | 省略、基于前几轮答案计算 |
| D3 纠正 | 2 | ① 某公司的净利润（合并口径）？② 不对，我要的是母公司报表里的数 | 用户纠正口径 |
| D4 比率 | 3 | ① 某公司营收？② 那研发费用呢？③ 用这两个数算一下研发费用率 | 省略公司、基于前几轮答案计算 |
| D5 期间 | 3 | ① 某公司本期经营现金流？② 上年同期呢？③ 增长率是多少？ | 省略公司与指标、基于前几轮答案计算 |

**每一轮记录的内容**：
- 用户说的原话（带省略和指代）；
- 写全了的独立问题，采用 benchmark_v1 的模板风格，作为改写的目标；
- 本轮答案、所需事实、推导式；
- 本轮考察的现象，以及它指向前面的哪几轮。

**单位与小数位**：每一轮都写明，例如「（亿元，四舍五入保留两位小数）」。这样考察的只是指代和省略，不把格式继承的问题混进来。

**规模与划分**：
- 划分方法：沿用 benchmark_v1 的划分规则，按事实组合分组，固定种子 20261016，Dev 与 Test 之间文字相似度不超过 0.8。
- 候选池：全部 10,759 段对话、36,643 个轮次，都已用 Agent 的计算器独立复算，结果全部一致。

| | 对话数 | 轮次数 | D1 / D2 / D3 / D4 / D5 |
| --- | --- | --- | --- |
| Dev | 26 | 78 | 8 / 5 / 4 / 4 / 5 |
| Test | 52 | 156 | 16 / 10 / 8 / 8 / 10 |

Dev 与 Test 之间没有共享的事实组合。

**与 benchmark_v1 的重叠**：v2 使用的事实中，有 38 条（Dev）和 58 条（Test）也出现在 v1 的 Test 中。
- 本轮只评估对话层的策略，不改动检索、核验和单题 Agent 的任何设置。v1 Test 的登记配置已经冻结，所以这种重叠不会影响 v1 Test 的结论。
- 这里如实记录，供审阅时判断。

**冻结前的质量检查**（需要少量额度）：
1. 每个后续轮次连同前文一起，交给两个 Judge 判断：指代或省略是否有唯一的合理理解。任一 Judge 认为有歧义就删除，用后备对话替补，规则与 v1 相同。
2. 用户抽查 10 段 Test 对话。
3. 冻结：只保存题面（各轮原话）的哈希；Test 答案不进 git。

## 二、四种对话策略

单题 Agent 一律使用 B3v2p 的冻结配置，各策略只在「把什么交给 Agent」这一点上不同：

| 策略 | 交给 Agent 的问题 | 跨轮带过去的内容 |
| --- | --- | --- |
| S1 每轮独立 | 只有本轮原话 | 无（作为下限） |
| S2 对话记录 | 前几轮的问题和系统给出的答案（数值、单位、选中的公司），加上本轮原话 | 文字记录 |
| S3 先改写 | 先调用一次模型，根据对话记录把本轮改写成完整的独立问题，Agent 只看改写结果 | 无 |
| S4 改写 + 证据延续 | 与 S3 相同，另外把前几轮答案所引用的证据块（只带被引用的块，字段精简），作为「已观测证据」放进本轮初始状态 | 已核验答案的引用证据 |

- **前几轮的答案用系统自己的输出，不用标准答案**。这样前一轮答错时，会如实影响后一轮，可以测量错误传播。
- **第 1 轮四种策略的输入完全相同**，只跑一次，结果供四种策略共用。
- **证据延续的边界（S4）**：
  - 只延续通过核验并发布的答案所引用的证据；
  - 延续来的证据与本轮新检索到的证据一样，受发布门禁约束；
  - 本轮引用的证据必须在本轮的观测中，而延续来的证据被视为本轮的初始观测；
  - 审计时检查每个延续来的证据块与索引原文逐字一致。

## 三、评估（Dev，事先登记）

- **运行**：
  - 26 段对话，第 1 轮共 26 次；
  - 后续 52 个轮次 × 4 种策略 = 208 次；
  - 再加上 S3、S4 的改写调用；
  - 每种策略跑 1 次，约 2.5–3 小时额度。
- **主要指标**：后续轮次（第 2 轮及以后）的准确率。评分规则与 benchmark_v1 相同。
- **区间**：按对话做 bootstrap，因为同一段对话内的轮次彼此相关。

**判定**：

| 编号 | 假设 | 标准 |
| --- | --- | --- |
| H1 | 先改写优于每轮独立 | S3 − S1 的后续轮次准确率差，95% 区间下界 > 0 |
| H2 | 证据延续不降低准确率 | S4 − S3 的区间下界 ≥ −5 个百分点 |
| H3 | 证据延续节省成本 | S4 相对 S3，后续轮次每轮的检索次数减少 ≥ 20% |

**描述性报告**：
- S2 与 S3 的比较（不预设方向）；
- 改写是否正确：程序检查改写结果是否包含标准独立问题中的公司、指标、期间和口径；
- 错误传播：前一轮答错和答对时，后一轮的错误率分别是多少；
- 每轮的 token 和模型调用次数随轮次的变化；
- 分对话类型、分现象的准确率。

## 四、服务与前端（工程部分，不影响评估）

- **服务端**：会话里保存对话历史，按用户隔离；每轮提问作为会话中的一次运行，按选定的策略组织输入。
- **前端**：改成聊天式界面，每一轮的步骤时间线照常实时推送；显示改写后的独立问题，方便用户确认系统理解得对不对。

## 已知局限

- **对话由模板生成**，用户说法的多样性不如真实对话。每类现象只有 2 种说法变体。
- **用户纠正只覆盖「合并 → 母公司」一种情形**。
- **样本量**：每种策略只跑 1 次，Dev 只有 52 个后续轮次，区间会较宽，只能检测较大的差异。
