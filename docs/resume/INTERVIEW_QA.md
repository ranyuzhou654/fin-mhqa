## Q1. Docling 是什么？chunk 怎么做，表格数据怎么处理？数据库用的什么？chunk 存进去是什么样子？

（2026-10-19）

### Docling 是什么

Docling 是 IBM 开源的文档解析工具，把 PDF 转成带结构的文档，标出标题、正文和表格，并给出表格每个单元格的行列位置。核心是两个模型：

- **版面分析模型**：识别页面区块类型；
- **TableFormer**：识别表格结构，输出单元格的行列和跨行跨列信息。

**本项目的配置**：TableFormer 用 ACCURATE 模式，开启单元格匹配，关闭 OCR（半年报 PDF 自带文字层），本地 CPU 4 线程离线运行。

**为什么换成 Docling**：最初用 PyMuPDF + pdfplumber 写规则解析，出现多行表头被拆碎、整张利润表漏检、无框表格只能靠文字对齐等问题。先用 5 页难例做对照，确认改善后才全量替换。最终 1,750 页解析 0 失败。

### chunk 怎么做

按章节树遍历，产出三种块：

| 类型 | 数量 | 规则 |
| --- | --- | --- |
| 正文 `text` | 3,719 | 同一章节内累积段落，约 350 token 切分，上限 450，在句号、分号处断开 |
| 表格 Markdown `table_md` | 2,823 | 每片最多 20 行、12 列，每片重复表头 |
| 表格键值 `table_kv` | 2,780 | 同一片表格改写成「行名：列名 数值，……」 |

token 用 bge-m3 的分词器计算。

### 表格具体处理

1. **还原网格**：按跨行跨列信息铺回二维网格。单元格占位冲突的表（32 张）不当作结构化表格，只保留原文。
2. **表头**：
   - 两层表头展平为「父 / 子」；
   - 表格中间出现新的「期末 / 期初」表头时，拆成新的一段；
   - 识别不出的列标成「列名未识别」，不去猜。
3. **跨页合并**：只有在上一张表顶到页底、本页的表从页顶开始、列数相同、标题和单位不冲突时，才合并。
4. **切片**：按行列切开，每片都保留行名列。
5. **双份输出**：Markdown 给模型读；键值让「行名 + 列名 + 数值」在同一行，利于 BM25 命中。
6. **单位**：记录单位和单位来源。2,749 个表格块自身没有标单位，由 Agent 的上下文读取工具去报告级的单位说明中查找。

### 数据库

检索层**没有用数据库**，语料只有 9,322 条：

- `faiss.index`：FAISS `IndexFlatIP` 精确检索，向量先做 L2 归一化，内积即余弦相似度，bge-m3 输出 1,024 维；
- `bm25/`：bm25s（Lucene 变体，k1=1.5，b=0.75），jieba 分词加财务词典；
- `chunk_meta.jsonl`：块的原文和元数据，检索服务启动时全部读入内存；
- `manifest.json`：记录各文件的 SHA256，检索服务启动时核对，不一致就拒绝提供服务。

**为什么不用向量数据库**：这个规模下精确检索已经足够快；扩大到上百倍时，可以换 HNSW 或 IVF 这类近似索引。服务层另有一个 SQLite，只存用户、会话和事件。

### chunk 存进去的样子

五粮液合并利润表（第 36 页）的同一片表格：

```
【五粮液 | 2025年半年度报告 | 第八节 财务报告 > 二、财务报表 > 3、合并利润表】
表：3、合并利润表　单位：元　币种：未标注
| 项目 | 2025年半年度 | 2024年半年度 |
|---|---|---|
| 其中：营业收入 | 52,770,984,383.52 | 50,648,026,578.65 |
```

```
【五粮液 | 2025年半年度报告 | 第八节 财务报告 > 二、财务报表 > 3、合并利润表】
表：3、合并利润表　单位：元　币种：未标注
其中：营业收入：2025年半年度 52,770,984,383.52，2024年半年度 50,648,026,578.65
```

**元数据字段**：
- **定位**：`chunk_id`（内容哈希）、`company`、`source_sha256`、`page_start/page_end`（物理页码）、`section_path`；
- **表格**：`table_title`、`unit`、`unit_source`、`parent_table_id` + `part`；
- **质量**：`quality_flags`。

**前缀的作用**：每块开头的「【公司 | 报告 | 章节】」既让块独立可读，也把公司名和报表名写进了向量与 BM25 的内容里。

### 可能被追问的三点

1. **副本问题**：Markdown 与键值两种块内容重复，使 Recall 偏低，还会造成 RRF「分票」，即两个副本被两路分别召回，各得一路分数，在截断时一起被丢掉。
2. **超长块**：有 258 个块（2.77%）超过 1,024 token，嵌入时被截断，返回给 Agent 的仍是完整原文。
3. **正文过碎**：正文块的中位数只有 54 token。

依据：`scripts/run_docling_pilot.py`、`src/finmhqa/ingest/docling_adapter.py`、`src/finmhqa/ingest/chunk.py`、`src/finmhqa/ingest/structure.py`、`src/finmhqa/retrieval/build_index.py`、`index/manifest.json`、`index/chunk_meta.jsonl`、`docs/system/DOCLING_CORPUS_RESULTS.md`。

## Q2. 面试官可能追问的这三个问题，应该怎么改进？

（2026-10-20）

### 先核实影响（作答时重新统计）

- **超长块不影响现有评测**：258 个被截断的块中键值块 160 个、Markdown 块 98 个。298 条基准事实分布在 97 个块里，**全部未被截断**，所以现有评测不受影响。被截断的主要是担保合同、子公司列表等文字型表格：中位数只有 18 行，却有约 1,215 token，长在单元格文字上，不在行数上。
- **碎片正文的构成**：3,719 个正文块中有 1,347 个不到 30 token。多为「□适用 ☑不适用」勾选模板，以及「（2）按坏账计提方法分类」「单位：股」这类与表格分离的表格标题。

### 问题 1：副本重复 → 改为按「证据单元」检索

**改进**：
1. **按单元融合**：把同一片表格（`parent_table_id` + `part`）的两个副本视为一个证据单元。每一路召回后先取单元内的最好名次，再对单元做 RRF。分票问题随之消失；返回时给 Markdown 原表，附带键值版。
2. **按通道分工（可选）**：向量索引只放 Markdown 块，BM25 只放键值块，每一路里不再有重复，索引也小一半。
3. **指标同步**：Recall 和 nDCG 按证据单元计算。

**验证**：先离线跑检索评测（不消耗模型额度），要求 Hit@5 不降，并确认因分票丢失的「伊利股份净利润」被找回；然后登记实验，在 Dev 上跑 Agent 端到端。

### 问题 2：超长块被截断 → 按 token 预算切分

**改进**：
1. 每片控制在约 800 token（含表头），按行累加，超出就新起一片；
2. 单个单元格过长时切分单元格本身，每段都带上行名；
3. 只重新切分和嵌入这 258 个块。

**验证**：确认所有块都不超过 1,024 token；现有指标应保持不变；另补「担保额度」类的探测题，验证这类问题的命中率提高。

**表述边界**：目前不影响评测，是为真实用户提问做准备，不能说成「准确率提升」。

### 问题 3：正文过碎 → 合并而不删除

**改进**：
1. 「☑不适用」并入同一章节的相邻块，不丢弃，因为它对「无法回答」类题目有信息量；
2. 表格前紧挨的短标题和单位行并入表格块，作为说明头；
3. 同一章节内短于约 100 token 的段落继续合并，到 350 token 左右为止。

**验证**：正文块数量明显下降；观察检索 30 题集中 4 道「变动原因」类文字题的指标，其中现有唯一的失败题（五粮液经营现金流增加的原因）正属此类。

### 相关改进：续表块加上上下文

「资产总计」召回不到，是因为它在长表最后一个续表块里，缺少「这是资产负债表合计部分」的线索。可以在续表块的说明头中补上「合并资产负债表（续）：负债和所有者权益」。

### 顺序与纪律

建议顺序是 1 → 3 → 2：问题 1 已测到会实际丢失证据，问题 3 有现成失败题可观察，问题 2 目前不影响评测。

每项都按项目的一贯流程：先登记设计与判定标准，再离线评测检索，通过后在 Dev 上跑 Agent，不改动已登记 Test 的配置。

依据：`index/manifest.json`（`embedding_truncated_chunk_ids`）、`data/bench/ledger_v1/facts.jsonl`、`index/chunk_meta.jsonl`、`docs/experiments/RETRIEVAL_METRICS_V1.md`（RRF 分票与资产总计召回问题）、`docs/system/M2_V2_RESULTS.md`（唯一失败题）。
